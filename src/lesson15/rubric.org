* 評価方針と配点割合
シラバスの評価基準（5段階評価：S / A / B / C / D）に基づき、以下の割合で総合評価を行います。

| 評価項目 | 配点割合 | 評価の観点 |
|----------+----------+------------|
| 1. 授業の事前準備、授業参加態度、発表、討論等 | 30% | 毎回の環境準備、プロンプトの工夫、対話型デバッグへの積極性、F12での検証姿勢 |
| 2. 課題レポート、試験等 | 70% | 成果物（Webページ）の完成度、コードの理解度説明（Read & Verify）、適切なGitコミット・GitHub管理 |

* バイブコーディング授業における評価観点（ルーブリックマトリクス）

** 観点A：プロンプト思考・要求定義力（配点割合：20%）
AI（GitHub Copilot）に対し、意図通りのコードを出力させるための条件・制約指定の具体性を評価します。

| 評価 | 水準 | 評価基準詳細 |
|------+------+--------------|
| S (秀) | 卓越 | 目的・構造・デザイン（Vibe）・制約条件（HTMLタグ指定、CSSクラス利用、JS関数明示等）を論理的に構成したプロンプトを作成・実行できる。 |
| A (優) | 良好 | 必要な条件や制約を概ね含めたプロンプトを作成し、AIから目的に近いコードを引き出すことができる。 |
| B (良) | 標準 | 指示の具体性がやや不足し、AIの出力に対して複数回の修正指示（対話）を重ねて意図する結果に到達できる。 |
| C (可) | 課題あり | 「良い感じにして」等の曖昧な指示が多く、意図しないコードが出力された際に対処のプロンプトを出せない。 |
| D (不可) | 未到達 | プロンプトの入力が行えない、または指示内容が著しく不足している。 |

** 観点B：コード理解度・解読力（Read & Verify）（配点割合：20%）
AIが生成したコードの仕組みや構造を自力で解読・説明できる能力を評価します。

| 評価 | 水準 | 評価基準詳細 |
|------+------+--------------|
| S (秀) | 卓越 | AIが生成したHTML構造、CSSプロパティ、JS（DOM操作・非同期処理等）の各行の役割を正確に理解し、他者やCopilotに的確に解説・質問できる。 |
| A (優) | 良好 | 生成コードの主要な構造や関数の役割を理解しており、基本的な質問に正しく回答できる。 |
| B (良) | 標準 | コードの全体的な動きは把握しているが、特定のプロパティや関数の意味の理解に一部不十分な点がある。 |
| C (可) | 課題あり | AIの出力コードを単にコピー＆ペーストするのみで、コードの意味や構造をほとんど理解していない。 |
| D (不可) | 未到達 | コードの動作や内容に関する説明が全くできない。 |

** 観点C：対話型デバッグ・検証能力（配点割合：20%）
ブラウザのデベロッパーツール（F12）を活用し、エラーや意図しない挙動に対処する能力を評価します。

| 評価 | 水準 | 評価基準詳細 |
|------+------+--------------|
| S (秀) | 卓越 | F12のコンソールエラーやDOM構造を観察し、エラー文をCopilot Chatに的確に伝えて迅速に自力解決できる。 |
| A (優) | 良好 | F12コンソールの確認を行い、Copilot Chatの支援を受けながらエラー原因を特定・修正できる。 |
| B (良) | 標準 | エラー発生時に教員やTAの指摘を受けてからF12を開き、Copilot Chatで修正を行う。 |
| C (可) | 課題あり | エラーが出ても放置するか、F12での確認を行わずに勘でプロンプトを再入力し続ける。 |
| D (不可) | 未到達 | デバッグ作業を行えない、またはエラーに対処しようとしない。 |

** 観点D：成果物（Webページ）の完成度・表現力（配点割合：25%）
課題要件（HTMLセマンティクス、CSSスタイリング、JS動的機能）を満たしたフロントエンド作品のクオリティを評価します。

| 評価 | 水準 | 評価基準詳細 |
|------+------+--------------|
| S (秀) | 卓越 | HTML/CSS/JSの仕様を正しく満たし、レスポンシブ対応やUI/UXの配慮が行き届いた完成度の高いWebページを作成できている。 |
| A (優) | 良好 | 課題の基本要件を満たしており、見た目や動作に大きな不備がないWebページを作成できている。 |
| B (良) | 標準 | 基本要件の大部分を満たしているが、デザインの崩れや一部機能の未実装が見られる。 |
| C (可) | 課題あり | 要件の一部しか満たしておらず、表示や動作に複数の問題が残されている。 |
| D (不可) | 未到達 | 課題成果物が提出されていない、または動作しない。 |

** 観点E：GitHub開発環境の活用・管理（配点割合：15%）
GitHub Codespacesの適切な運用と、バージョン管理（Gitコミット）の習慣化を評価します。

| 評価 | 水準 | 評価基準詳細 |
|------+------+--------------|
| S (秀) | 卓越 | 意味のある単位で適切なコミットメッセージを記述してGitコミット・プッシュを行い、Codespaces環境を円滑に管理できている。 |
| A (優) | 良好 | 授業課題の区切りごとにコミット・プッシュを行っており、リポジトリが適切に管理されている。 |
| B (良) | 標準 | 最終提出時にまとめてコミットを行うなど、履歴管理の細やかさにやや欠ける。 |
| C (可) | 課題あり | コミット手順に不安があり、教員のサポートなしではプッシュが行えない。 |
| D (不可) | 未到達 | リポジトリの作成や成果物のプッシュが行われていない。 |

* 総合評価基準（成績つけの目安）
- **S (90〜100点)** :: 全ての観点で卓越・良好であり、特にプロンプト思考と自力デバッグ能力が高い。
- **A (80〜89点)** :: 全ての観点で良好な水準に達しており、課題要件を確実に達成している。
- **B (70〜79点)** :: 平均的な到達水準であり、標準的な課題解決が行えている。
- **C (60〜69点)** :: 合格最低限の水準。自力解決力や理解度に課題が残る。
- **D (0〜59点)** :: 不合格。出席不足、課題未提出、または到達水準に達していない。
