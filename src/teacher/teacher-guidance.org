#+TITLE: 教員向け補足説明ペーパー：バイブコーディングを活用したプログラミング授業の狙いと運営方針
#+SUBTITLE: プログラミング中級（デジタルイノベーション学科）授業運営ガイド
#+AUTHOR: 中鉢 欣秀
#+DATE: 2026-09-17

* 1. 授業導入の背景と教育的意義
  従来のプログラミング初学者向け授業（HTML/CSS/JavaScript）では、構文（Syntax）の暗記や、タイピングミス・セミコロンの打ち忘れといった単純な文字エラーによる挫折が頻発していました [58]。
  本授業では、最新のAIペアプログラマー（GitHub Copilot）を活用する**「バイブコーディング（Vibe Coding）」**を導入し、以下の教育効果の獲得を目指します：

  - **概念理解（目的・設計）の優先** :: 手打ちのストレスを削減し、「どのような画面・機能を作りたいか（目的）」や「Webページ全体の構造」の理解に思考リソースを集中させます [58]。
  - **コードレビュアー視点の育成（Read & Verify）** :: AIが生成したコードを実行・観察し、その構造や動作原理を読み解く「リバースエンジニアリング」的な学習アプローチを養います [58, 62]。
  - **プロンプト思考（要求定義力）の獲得** :: 曖昧な指示では意図通り動かない体験を通じ、AIに対して論理的な制約条件・文脈を与える「仕様策定能力」を養います [58]。

* 2. クラウド環境（GitHub Education / Codespaces）によるインフラ標準化
  - **環境構築トラブルの排除** :: ブラウザ上で全機能が完結する Visual Studio Code（GitHub Codespaces）を採用し、学生個人のPC（Mac/Windows）やOS環境の違いによる環境構築トラブルを排除します [59]。
  - **全額無料での教育利用** :: 教員および学生が GitHub Education（Student Developer Pack）に登録することで、GitHub Codespaces（月180時間無料）および GitHub Copilot を無償で利用できます [59]。
  - **統一開発環境の配布** :: 授業用OrganizationでDevcontainerおよびテンプレートリポジトリを用意することで、履修生全員がワンクリックで同一のCopilot利用環境を立ち上げられます [59]。

* 3. セキュリティ・プライバシーとデータ保護設定
  - **入力データの非保持** :: GitHub Education / Businessのアカウント設定により、学生や教員が入力したプロンプトや生成コードがモデル再学習（教師データ）に利用されるのを防止します [81, 82]。
  - **二段階認証（2FA）と権限管理** :: アカウントの不正アクセス防止のため、全履修生に2FAを設定させ、Organizationのアクセス権限を適切に制御します [83, 84, 114]。
  - **生成コードの検証指導** :: AIが生成するコードには潜在的な不備や脆弱性が含まれる可能性があるため、定期的なセキュリティレビューやF12デベロッパーツールによる検証姿勢を徹底します [82, 85, 114]。

* 4. 授業運営における4大指導ノウハウ
  - **1) ライブプロンプティング（Live Coding with AI）** ::
    教員が画面共有を行い、「曖昧な指示（悪い例）」と「構造・制約を明記した指示（良い例）」を入力し比べ、出力精度やコード構造の違いをリアルタイムに実演します [62]。
  - **2) 変奏曲（Variation）演習** ::
    AIが生成したコードをそのまま丸呑みさせず、「色を変える」「テーブルを追加する」など、学生各自にアレンジ用プロンプトを入力させて動作変化を実験させます [62]。
  - **3) コード解読の義務化（Read & Verify）** ::
    Copilot Chatに対し「このコードの仕組みを初心者向けに解説して」と質問させ、AIが出力したコードの各行の役割を自力で説明・解読させます [62]。
  - **4) 対話型デバッグの体験** ::
    あえて教員が一部のコードを崩したりエラーを起こさせ、ブラウザのデベロッパーツール（F12）のコンソールエラー文を Copilot Chat に貼り付けて自力修復させるデバッグプロセスを体験させます [61, 62]。

* 5. 成績評価（ルーブリック）との連動方針
  シラバスの評価割合（授業参加・態度 30%、課題・試験等 70%）に基づき、以下の観点でルーブリック評価を行います [72]：
  - **プロンプト思考（要求定義力）** :: 条件・制約（HTMLタグ、CSSクラス、JS関数等）を整理したプロンプトが作成できているか。
  - **コード解読力（Read & Verify）** :: 生成コードの主要な構造や関数の役割を説明できるか。
  - **対話型デバッグ・検証能力** :: F12コンソールエラーを確認し、Copilotへの再指示でエラーを自力解決できるか。
  - **成果物の完成度 & Git管理** :: 要求仕様を満たしたフロントエンド作品であり、適切なコミットメッセージでGit履歴が管理されているか。
