* 1. 概要・実演目的
本資料は、授業中に教員が画面共有を行い、学生に対して**「F12デベロッパーツールの活用法」**と**「GitHub Copilot Chatを用いた対話型デバッグ手順」**をライブで実演解説するためのシナリオ（10〜15分想定）です。

**学習効果・指導上のねらい** [62]:
- プログラムが意図通り動かない時、勘でプロンプトを入力し直すのではなく、まずF12ツールで原因を特定する習慣を身につけさせます。
- F12コンソールに出力された赤文字のエラーメッセージを Copilot Chat にそのまま伝えて解決させる「対話型デバッグ」の手順を示します [39, 43]。
- ブラウザの Elements タブで DOM 構造やクラス属性の変化を目視観察させ、JavaScriptの動作（DOM操作）を可視化・理解させます [61, 62]。

* 3. 詳細実演シナリオ（台本・操作手順）

** ステップ1：F12ツールの起動と正常状態の観察（2分）
*** 操作手順
1. ブラウザ（Google Chrome / Microsoft Edge）で演習Webページを表示する。
2. キーボードの ~F12~ キー（または右クリック ➔ ~検証~）を押し、デベロッパーツールを開く。
3. **Elements（要素）パネル** を選択し、HTML構造を表示する。
4. **Console（コンソール）パネル** を選択し、エラーが出ていない状態を確認する。

*** 教員の口頭説明（スクリプト）
#+BEGIN_QUOTE
「みなさん、Webページがブラウザでどう作られているかを見る魔法のツールが『F12デベロッパーツール』です。
F12キーを押すと右側にパネルが開きます。
まず『Elements』タブを見てください。ここには今画面に映っているHTMLの骨格（DOM構造）が表示されています。
次に『Console』タブを開いてみましょう。現在は何も赤文字が出ていませんね。これが正常な状態です。」
#+BEGIN_QUOTE

---

** ステップ2：意図的なバグの混入とエラー観察（3分）
*** 操作手順
1. VS Code / Codespaces のエディタを開く。
2. JavaScriptコード内の HTML ID 指定をあえて間違えさせる（例: `#bg-toggle` ➔ `#bg-toggle-wrong`）。
3. 保存してブラウザを更新し、ボタンをクリックする（動かない）。
4. F12の **Console タブ** を開く。

*** 発生するエラー例（赤文字）
#+BEGIN_EXAMPLE
Uncaught TypeError: Cannot read properties of null (reading 'addEventListener')
    at script.js:5:15
#+END_EXAMPLE

*** 教員の口頭説明（スクリプト）
#+BEGIN_QUOTE
「あえてJavaScriptコードの一部を間違えてみましょう。
ボタンを押しても背景色が変わりませんね？
ここで焦って『コード全体を作り直して』とAIに頼むのは間違いです。まずF12のConsoleタブを見ます。
赤文字で『Uncaught TypeError: Cannot read properties of null』と出ていますね。
これは『指定したIDのボタン要素が見つからなかったので、クリックイベントを設定できませんでした』というブラウザからの警告です。」
#+BEGIN_QUOTE

---

** ステップ3：Copilot Chat へのエラー伝達と対話デバッグ（4分）
*** 操作手順
1. F12コンソールの赤文字エラーメッセージ全体をドラッグしてコピーする。
2. VS Code / Codespaces の **Copilot Chat** パネルを開く。
3. 以下のデバッグプロンプトを入力して送信する。

*** 実演用プロンプト
#+BEGIN_EXAMPLE
ブラウザのF12コンソールで以下のエラーが発生してボタンが動作しません。
原因を特定し、修正すべきコードを教えてください。

【エラーメッセージ】
Uncaught TypeError: Cannot read properties of null (reading 'addEventListener')
#+END_EXAMPLE

*** 教員の口頭説明（スクリプト）
#+BEGIN_QUOTE
「エラーが出たら、その赤文字をそのままコピーして Copilot Chat に貼り付けます。
『このエラーが出たので原因と修正案を教えて』と頼むだけです。
Copilot は『HTML内のIDとJavaScriptで取得しているIDが一致していない可能性があります』と原因を的確に指摘し、正しい修正コードを教えてくれます。」
#+END_QUOTE

---

** ステップ4：修正コードの適用と復旧確認（3分）
*** 操作手順
1. Copilot が提案した修正コード（ID名の修正）を JavaScript ファイルに反映して保存する。
2. ブラウザ画面を更新する。
3. ボタンをクリックし、背景色が切り替わることを確認する。
4. F12の **Console** で赤文字エラーが消えたことを確認する。
5. F12の **Elements** タブを開き、ボタンを押すたびに `<body>` タグの `class="dark-mode"` がリアルタイムで追加・削除される様子を見せる。

*** 教員の口頭説明（スクリプト）
#+BEGIN_QUOTE
「修正コードを貼り付けて再読み込みしてみましょう。
ボタンを押すと無事に背景が切り替わりましたね！
F12のConsoleタブを見ても、赤文字エラーは消えています。
さらにElementsタブを開いたままボタンを押してみてください。`<body>` タグの class 属性が `dark-mode` に動的に変化しているのが目で見えますね。
このように、JavaScriptのプログラムが実際に画面（DOM）をどう動かしているかをF12で確認するのが『Read & Verify（観察と検証）』の基本です。」
#+BEGIN_QUOTE

* 4. 学生向けデバッグポイントのまとめ

授業の最後に学生に強調する「デバッグ3箇条」：

1. **「動かない時はまず F12」**
   - 画面が崩れたりボタンが動かない時は、勘で直さずまず F12 キーを押す。
2. **「Console の赤文字はそのまま Copilot へ」**
   - 赤文字エラーはトラブル解決の宝箱。コピーして Copilot Chat に投げれば9割解決する [39, 43]。
3. **「Elements タブで裏側の変化を目で見る」**
   - JavaScriptが正しく動いているかは、ElementsタブのHTML変化を目視して確認する [61, 62]。
